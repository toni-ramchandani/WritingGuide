# Article Writing Desk Reference — v1.0

## Before drafting

**Question:** What engineering problem is worth solving, and what conclusion can we defend?

**Brief:** reader → transformation → thesis → tension → strongest counterargument → unique contribution → scope.

**Coverage:** breadth (context/alternatives); depth (internals and causal paths); height (decisions, costs, limits).

**Research:** primary sources → claim register → contradictory evidence → versions/methods → evidence gaps.

**Figures:** each answers a question; specify entities, arrows, assumptions, sources, caption, alt text. Sketch before mechanism-heavy prose.

## During drafting

**Argument:** Problem → Tension → Mechanism → Evidence → Trade-offs → Judgment. Roles, not compulsory headings.

**Paragraph:** observation/claim → mechanism → example/evidence → qualified implication. Vary the structure naturally.

**Integrity:** say who observed what; name the conditions; label illustrative calculations; don't invent first-person deployments, trials, metrics, source text or tests.

**Voice:** specific and clear; no hollow hype, repeated recap, empty benefits list, fake certainty, or excessive one-line sentences.

## Before publishing

**Review in order:** Technical validity → evidence → argument → diagrams → craft/Medium.

**Stop publication for:** materially false design, unsupported core conclusion, invented evidence, misleading figure, omitted decisive counterexample, improper rights/confidentiality handling.

**Sign-off:** no BLOCKERS; revised complete article reconciled against brief, claim register, visuals, links and date/version anchors.

**Single sentence to remember:** Investigate → Explain → Substantiate → Synthesize. Make the reader capable of a better engineering decision.
